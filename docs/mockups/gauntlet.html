Gauntlet, and where its instructions live

The Gauntlet spins a wheel over the catalogue and hands you one game. Everything it can do is already built; what is missing is the page ever saying so. Three layouts keep the whole feature set and differ only in where the page explains itself — and each rewrites that explanation in Royal mode, where the wheel stops reading the catalogue and starts reading a list you built. Every block below is drawn with the shipped components: Box, Button, Tabs, Chip, ToggleSwitch, GameCard, ExpandMenu, Scrollbar, and icons from shared/ui/svg.

What every layout has to keep

Read off the page as it is built today. A variant that drops any of these is not a candidate.

Wheel: canvas wheel, timer spin duration, button cycling Loading… / Spinning… / Spin

Filters drawer: left edge, hidden while Royal is on

Lists drawer: right edge — Gauntlet / Royal (n) / History, Royal splitting into List and Saved

Settings drawer: bottom right — Royal mode, Music, Bounce back, volume, spin time

Winner: GameCard plus name, year, type, platforms, genres, modes, themes, languages, stats, summary, storyline, media, release dates

Backdrop: the winner's artwork through BGImage

A

Ribbon over the stage

The stage stays exactly as it is and the explanation arrives as one more Box directly above the wheel — where a first-time visitor is already looking. It is dismissible and stays dismissed for that browser. The cheapest of the three: nothing moves, one panel appears.

C

Two acts

Before the first spin the page is a setup view: the mode switch is the headline, the description is the whole point of the screen, and the filter or list summary sits under it. After the spin it becomes the stage and the description is gone. The explanation costs nothing once you are playing, because it occupies the moment when nothing is happening anyway.

How any of them would be built

Notes that apply whichever variant is picked.

  • The description is one component reading isRoyal from useStatesStore; the two copies are its only branch.
  • Every block is a Box — the page renders over BGImage, and text on the bare background is washed out by whatever artwork the winner brought.
  • The mode switch stays in the Settings drawer. Where a variant promotes it (C), both controls call the same setRoyal; they do not keep separate state.
  • Hiding the Filters drawer in Royal is existing behaviour — the page already renders that ExpandMenu only when !isRoyal.
  • Icons used above are SvgGauntlet, SvgCrown, SvgClose, SvgSettings, SvgRandom, SvgListBullet and SvgWheelPointer, all already in shared/ui/svg.

Colours, spacing and radii are the project's own tokens: the :root block above is generated from apps/web/src/lib/app/styles/vars by bun --filter web sync:tokens. The panels, buttons, tabs, chips, toggle, card, scrollbar and drawer chrome are drawn from the shipped components' own SCSS, and the icons are the real paths out of shared/ui/svg. The typeface is substituted — Hanken Grotesk stands in for ApercuPro, whose licensed file cannot be served from a third-party host.
